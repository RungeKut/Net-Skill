# Бэкап перед правкой: /export RouterOS, копия x-ui.db и экспорт шаблона панели

## Правило

Перед любой правкой конфигурации — сохранить текущее состояние. Далее бэкапы не удалять, пока изменение не подтверждено.

## RouterOS: /export

```
/export file=pre-fix-2026-10-21
```

Забрать к себе (не оставлять на роутере — места мало):

```bash
scp user@192.0.2.1:pre-fix-2026-10-21.rsc .
```

Бинарный `/system backup` — дополнение, не замена. Он содержит состояние в формате, зависимом от версии RouterOS, и нечитаем текстовым редактором. `/export` читается всегда. Подробнее — [10-02](../10_API/10-02_export_вместо_print.md).

## 3x-ui: sqlite3 .backup

База панели — `/etc/x-ui/x-ui.db`. Перед правками (смена шаблона, обнуление flow, правка клиентов):

```bash
systemctl stop x-ui
sqlite3 /etc/x-ui/x-ui.db ".backup /root/x-ui-backup-pre-fix-2026-10-21.db"
systemctl start x-ui
```

Панель **останавливать обязательно**. Бэкап без остановки — риск получить битую копию из-за незавершённых транзакций.

## Шаблон конфигурации Xray

В панели 3x-ui шаблон хранится в базе. Отдельный экспорт:

- Панель → Настройки Xray → Копировать шаблон → сохранить в файл.
- Или через API панели (токен).

## Имена

Формат: `префикс-суть-ГГГГ-ММ-ДД`. Примеры:

- `pre-fix-2026-10-21.rsc` — экспорт роутера перед правкой;
- `x-ui-backup-pre-xhttp-2026-10-21.db` — бэкап базы панели;
- `vm-template-xhttp-2026-10-21.json` — экспорт шаблона.

## Чем подтверждено

Процедура применялась при смене транспорта (TCP → XHTTP), обнулении flow в базе, переносе VM. Каждый раз: `/export` роутера, `.backup` x-ui.db при остановленной панели, экспорт шаблона. Ни один бэкап не оказался битым. Старые бэкапы удалялись только после недели без нареканий.
