# DNS при сплит-туннеле отправляется напрямую

## Как устроено

Правило маршрутизации в Xray: IP публичных DNS-резолверов (`77.88.8.8`, `8.8.8.8`, `8.8.4.4`) → `direct`. DNS-запрос на порту 53 → встроенный DNS Xray (`dns-out`). Ни один DNS-запрос не уходит в туннель.

```
"rules": [
  { "ip": ["77.88.8.8", "8.8.8.8", "8.8.4.4"], "outboundTag": "direct" },
  { "port": 53, "outboundTag": "dns-out" }
]
```

DNS Xray настроен на те же резолверы: `77.88.8.8` (Яндекс) и `8.8.8.8` (Google), `queryStrategy: UseIPv4`.

## Почему напрямую, а не DoH через туннель

DoH через туннель означает:

- задержка на каждый DNS-запрос (дополнительный RTT до VPS и обратно);
- усложнение отладки: при неработающем туннеле не резолвится ничего, включая адреса для диагностики;
- внешний резолвер не узнаёт список доменов, которые клиент собирается посещать (белый список не раскрывается).

## Локальные имена

Локальные имена (`nas.local`, `printer.local`) резолвятся через `hosts` в конфиге Xray (шаблон панели). Отдельный локальный DNS-сервер не требуется. Если имя не добавлено в hosts, его надо добавить там, а не включать DNS-прокси через туннель.

## Правило снифинга

В inbound с sniffing обязательно выставлять `routeOnly: true`. Иначе сниффер вычитывает SNI из первого пакета соединения, перезаписывает адрес назначения, и клиент, подключившийся к прокси по IP (а не по домену), уходит на настоящий сайт вместо туннеля.

## Чем подтверждено

Схема в постоянной эксплуатации: DNS-запросы к `77.88.8.8` и `8.8.8.8` идут напрямую, локальные имена резолвятся через hosts шаблона. При падении туннеля DNS продолжает работать. Sniffing с `routeOnly: true` включён на inbound внешних подключений.
