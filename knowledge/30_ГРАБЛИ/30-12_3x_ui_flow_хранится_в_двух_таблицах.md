# Flow клиента в 3x-ui хранится в таблицах базы

## Что происходит

После смены транспорта inbound (например TCP на XHTTP) клиенты перестают
подключаться. В логе Xray: `account ... is rejected since the client flow
is empty`. Reality-клиенты падают молча — соединение уводится в fallback,
в логе пусто.

Симптом пофайловый: на одном inbound (Reality, XHTTP-транспорт) два клиента
с разным flow ведут себя по-разному:
- у первого `flow=xtls-rprx-vision` (несовместим с XHTTP) — не подключается;
- у второго `flow=''` (пустой, допустимо для XHTTP) — работает.

Смена транспорта через правку inbound в панели (Настройки Xray → Inbounds)
не сбрасывает `flow` у клиентов.

## Почему

Панель 3x-ui хранит настройки клиентов в SQLite-базе
`/etc/x-ui/x-ui.db`. Генератор конфига читает `flow` из таблицы **clients**,
а не из настроек inbound. Пока в `clients.flow` висит `xtls-rprx-vision`,
генератор вписывает его в конфиг независимо от транспорта inbound.

При `security: reality` генератор по умолчанию вписывает vision,
даже если транспорт XHTTP или gRPC, где vision невалиден. Правка
`inbounds.settings` через панель на генерацию не влияет.

Сгенерированный `/usr/local/x-ui/bin/config.json` — единственная правда
о рантайме. Панель перезаписывает его при любом изменении настроек
и при каждом перезапуске.

## Как правильно

1. Остановить x-ui:
   ```
   x-ui stop
   ```

2. Обнулить `flow` у всех клиентов на нужном inbound (или у конкретных):
   ```bash
   sqlite3 /etc/x-ui/x-ui.db "UPDATE clients SET flow='' WHERE flow!='';"
   ```

   В таблице `clients` есть колонка `flow`; таблица `inbounds` содержит
   inbound-настройки, но колонки `flow` в `client_inbounds` нет — править
   только `clients`.

3. Перезапустить x-ui:
   ```
   x-ui restart
   ```

4. Сверить сгенерированный конфиг:
   ```bash
   grep flow /usr/local/x-ui/bin/config.json
   ```

   В каждой записи клиента `flow` должен быть пустой строкой или
   отсутствовать.

## Как неправильно

- Менять транспорт inbound через панель и ждать, что клиенты подхватят
  новый flow. Панель не обнуляет `clients.flow`, генератор продолжает
  вписывать старое значение.
- Править `/usr/local/x-ui/bin/config.json` вручную — панель перезапишет
  его при первом же перезапуске.
- Тратить время на `POST /login` панели через curl — 3x-ui отдаёт 403
  на /login при несовпадении Origin/Referer (анти-бот). Все правки —
  через sqlite3 напрямую.

## Чем подтверждено

2026-10-26: на рабочей панели 3x-ui v3.8.5 сменили транспорт inbound
с TCP на XHTTP. Два клиента на одном Reality-inbound: первый с
`flow=xtls-rprx-vision` перестал подключаться (лог Xray:
`client flow is empty`), второй с пустым flow работал. После обнуления
`clients.flow` через sqlite3 и перезапуска первый клиент заработал.
Повторно проверено: `grep flow` в сгенерированном config.json
показал пустой flow.
