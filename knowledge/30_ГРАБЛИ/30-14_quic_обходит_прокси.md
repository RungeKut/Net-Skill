# QUIC (UDP 443) обходит TCP-прокси

## Что происходит

При работающем SOCKS5-прокси (Proxifier, SocksCap, встроенный SOCKS5
клиента Xray) браузер показывает реальный IP машины, хотя curl с той же
машины через прокси видит IP выхода.

Симптом «пульсирующий»: на одной загрузке страницы браузер показывает
reality IP, на следующей — IP выхода. Это зависит от того, успел ли
браузер установить QUIC-соединение до таймаута.

Проверка через `cdn-cgi/trace`:
- строка `http=` должна быть `http/2` или `http/1.1` — трафик идёт
  через прокси;
- `http=h3` — трафик идёт по QUIC (UDP), прокси обойдён;
- `ip=` — если реальный IP, а не IP прокси/выхода — утечка
  подтверждена.

## Почему

HTTP/3 работает поверх QUIC — протокола на UDP. SOCKS5-прокси
и классические проксификаторы (Proxifier, SocksCap) проксируют
только TCP. QUIC-пакеты с UDP 443 летят напрямую, минуя прокси.

Браузер при старте соединения сначала пробует QUIC (если включён).
Если QUIC-пакет не получает ответа (прокси не пересылает, таймаут),
браузер через несколько секунд открывает обычное TCP-соединение.
На успешно загруженной странице итоговый протокол `http/1.1` или
`http/2`, но реальный IP уже утёк.

## Как правильно

### Вариант А (рекомендуемый) — отключить QUIC в браузере

В адресной строке: `brave://flags` (или `chrome://flags`) →
**Experimental QUIC protocol** → **Disabled**.

После обновления браузера флаг может сброситься. Контроль:
```
https://cdn-cgi/trace
```
`http=` должен быть `http/2` или `http/1.1`, не `h3`.

### Вариант Б — через политику Windows (Chromium)

Для managed-окружений:
```
QuicAllowed=0
```

### Вариант В — блокировать UDP 443 outbound фаерволом

Требует прав администратора:
```powershell
New-NetFirewallRule -DisplayName "Block QUIC outbound" -Direction Outbound `
  -Protocol UDP -RemotePort 443 -Action Block
```

Проверка после блокировки: те же `cdn-cgi/trace`.

## Как неправильно

- Проверять работу прокси только curl'ом — curl ходит по TCP,
  не видит утечку QUIC.
- Считать, что раз страница открылась и `http=` в `cdn-cgi/trace`
  показывает `http/2`, то всё в порядке — первый QUIC-запрос уже
  мог выдать реальный IP.
- Рассчитывать, что после отключения QUIC в браузере настройка
  сохранится после обновления — Chromium сбрасывает флаги
  (`brave://flags`) при обновлении версии.

## Чем подтверждено

2026-10-09: на рабочей машине (Windows 10, Brave) прокси через
SOCKS5 работал (curl показывал IP выхода 203.0.113.10), но браузер
на claude.ai выдавал ошибку региона с IP провайдера (198.51.100.7).
После отключения QUIC в `brave://flags` IP в браузере и curl совпали.
После блокировки UDP/443 фаерволом — тот же результат. Повторная
проверка через `cdn-cgi/trace`: `http=h3` до лечения, `http=http/2`
после.
