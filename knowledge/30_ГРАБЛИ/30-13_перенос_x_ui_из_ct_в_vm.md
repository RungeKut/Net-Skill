# Перенос 3x-ui между машинами — это перенос x-ui.db

## Что происходит

При переносе 3x-ui из контейнера (CT) в виртуальную машину (VM)
на Proxmox или между любыми другими машинами конфигурация теряется,
если переносить только сгенерированный конфиг.

После чистой установки 3x-ui и копирования
`/usr/local/x-ui/bin/config.json` панель при первом же перезапуске
перезаписывает config.json из базы. Все ручные правки в config.json
пропадают. Inbounds, клиенты, routing — всё возвращается к шаблону
по умолчанию, который в панели не настраивали.

## Почему

3x-ui хранит все настройки inbounds, клиентов и шаблон конфига
в SQLite-базе `/etc/x-ui/x-ui.db`. Сгенерированный
`/usr/local/x-ui/bin/config.json` — это дериват (производный файл),
который панель перезаписывает при каждом изменении настроек,
перезапуске панели или перезапуске службы x-ui.

config.json — единственная правда о рантайме, но не источник
конфигурации. Источник — БД.

## Как правильно

1. Перед миграцией сделать бэкап БД:
   ```bash
   cp /etc/x-ui/x-ui.db /root/x-ui-backup-$(date +%F).db
   ```

2. На новой машине установить **ту же версию** 3x-ui.

3. Остановить x-ui:
   ```bash
   x-ui stop
   ```

4. Заменить пустую БД на бэкап:
   ```bash
   cp /root/x-ui-backup-2026-10-05.db /etc/x-ui/x-ui.db
   ```

5. Запустить x-ui:
   ```bash
   x-ui restart
   ```

6. Панель перегенерирует config.json из БД — вся конфигурация,
   клиенты, шаблон перенесутся.

## Как неправильно

- Чисто установить 3x-ui, скопировать
  `/usr/local/x-ui/bin/config.json` со старой машины и ждать,
  что всё заработает. Панель перезапишет config.json при рестарте.
- Править config.json вручную на новой машине, не перенеся БД.
  Любая операция в панели сбросит правки.
- Переносить разную версию 3x-ui. Версия панели должна совпадать:
  схема БД могла измениться.

## Чем подтверждено

2026-10-05: миграция 3x-ui v3.8.5 из контейнера (CT) в виртуальную машину (VM) на Proxmox.
Первая попытка — скопирован config.json — после перезапуска панель
сбросила конфигурацию. Вторая попытка — перенесена `/etc/x-ui/x-ui.db`
той же версии панели — конфигурация восстановлена полностью.
