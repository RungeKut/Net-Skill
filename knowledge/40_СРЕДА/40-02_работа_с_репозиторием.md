# Работа с репозиторием

## Начало работы

```sh
git -C <корень> pull --rebase
```

Конфликт разбирать до работы: база знаний важнее текущей задачи.

## Что в репозиторий не попадает

Схема сети — **готовая карта для того, кто будет её ломать**. В набор
не попадает:

* адреса сетей и хостов, публичные IP;
* SSID и пароли к ним, профили безопасности;
* логины и пароли, ключи WireGuard (в том числе публичные);
* MAC-адреса, имена устройств и людей;
* пробросы портов, состав VPN, имена туннелей;
* пути, имена серверов и учётные записи рабочей машины.

Всё это живёт в `local/`, который под `.gitignore`
([40-03](40-03_локальные_данные_площадок.md)).

В примерах базы — документационные диапазоны `192.0.2.0/24`,
`198.51.100.0/24`, `203.0.113.0/24` и обобщённые «роутер А», `SSID-GUEST`.

Модель роутера и версия RouterOS — **можно**, они нужны в `applies_to`.

## После каждого изменения набора

Сразу, не в конце сессии:

```sh
git diff                        # 1. прочитать глазами
python tools/check_docs.py      # 2. общая проверка skill-skill
git add <файлы> && git commit -m "кратко что и почему"
git push
```

`tools/check_docs.py` — обёртка, одинаковая во всех наборах: вызывает
общую проверку из соседнего skill-skill. Своего кода проверок в наборе
нет; особые правила — только `tools/kit_local.py`, если понадобятся.

## Стоп-лист — только локальный

`tools/stoplist.txt` содержит приметы площадок этой машины: SSID, имена.
Лежащий в репозитории стоп-лист **сам публиковал бы то, что должен
скрывать**. Он в `.gitignore`, заводится руками при установке
([40-01](40-01_установка_и_окружение.md)). Не возвращать его под git.

## Что проверка ловит, а что нет

`check_docs.py` ловит:

* слова из общего и своего стоп-листов, регистронезависимо;
* IP-адреса вне документационных диапазонов;
* MAC-адреса, строки, похожие на ключи;
* файлы `local/`, попавшие в индекс git;
* текст коммита — хуком `commit-msg`.

**Не ловит** описание, по которому площадка узнаётся без единого адреса:
«роутер на LTE-модеме с гостевой сетью и туннелем до соседнего города».
За этим — `git diff` глазами.

## Автор коммитов

Задан **для клона**, без `--global`:

```sh
git config user.name "..."
git config user.email "..."
```

Не задан — не коммитить, а спросить человека, от какого имени публиковать.
Иначе в публичную историю уйдут глобальные рабочие имя и адрес. Без
соавторов и подписей ИИ в коммитах — включить на уровне агента
(skill-skill, 30-04, 40-04).

## Хук commit-msg — общий, в skill-skill

Проверяет текст коммита по тем же стоп-листам. Включается через
`core.hooksPath = ../skill-skill/hooks` — хук и проверка едут из
соседнего скилла, своего хука у набора нет.

## После git pull --rebase

Проверку прогнать заново и перечитать слитое: git сливает текст, а не
смысл. Особенно таблицы `INDEX.md`.

## Чем подтверждено

`python tools/check_docs.py` на полном наборе — ни одного совпадения;
`git ls-files local/` пуст.
